## 一、项目概述

锚点小程序（Day-Life-wanderer）是一款**个人成长工具**，核心理念：

> **四象限法（管当下）× 周复盘（看节奏）× 人生蓝图/星系（串主线）× 锚点输入（每天说一句）**

### 1.1 技术栈

| 层级 | 技术 |
|------|------|
| 前端 | React 18 + TypeScript + Vite + Tailwind + shadcn/ui（60+ 组件） |
| 状态 | zustand 5 + localStorage（key: `anchor-app-state-v2`） |
| 路由 | react-router 7（HashRouter） |
| 后端 | tRPC + Drizzle ORM + MySQL |
| AI | OpenAI SDK（gpt-5-mini） |
| 部署 | Railway（Node.js）+ GitHub Pages（静态） |
| 3D 视图 | Three.js（恒星/行星/卫星系统） |

### 1.2 项目结构

```
anchor-fullstack/
├── client/          # 前端（React + Vite）
│   └── src/
│       ├── pages/               # 页面（Home, Universe, Settings, etc.）
│       ├── components/          # 组件
│       │   ├── AnchorGalaxy.tsx   # 3D 星系视图
│       │   ├── galaxy/            # 星系相关组件
│       │   │   └── SubSpaceView.tsx  # 恒星子空间视图
│       │   └── weekly/            # 周视图
│       │       └── WeekGanttChart.tsx  # 甘特图
│       └── lib/                 # 工具库（i18n, utils, trpc）
├── server/            # 后端（tRPC routers + 定时任务）
│   ├── routers/             # API 路由
│   ├── _core/               # 核心逻辑
│   │   └── voiceTranscription.ts  # 语音转录
│   └── parseNatural.ts      # 自然语言时间解析
├── shared/            # 前后端共享
│   ├── taskRules.ts           # 任务规则（象限解析、状态映射）
│   └── taskStatusVisual.ts    # 卫星状态可视化（金色阶梯配色）
└── taro-app/          # 微信小程序骨架（Taro）
```

### 2.2 功能模块

#### 1. 四象限看板（Quadrant）
- 折叠式"快速输入"文本框，支持自然语言解析时间+项目
- 任务拖拽到象限，自动解析重要/紧急属性
- 任务编辑对话框（标题、截止时间、重要性、紧急判定、备注、关联项目）
- 任务列表视图（Board/List 切换）
- 任务恢复功能（已完成/已放弃任务可恢复为待办）

#### 2. 周视图（Week）
- **甘特图**：14 天窗口，支持缩放/拖拽/周导航
- 点击任务条 → 打开 TaskEditorDialog
- 拖拽任务条右侧手柄 → 调整截止时间（跨视图联动）
- 无截止时间任务：虚线边框 + 半透明标识
- 多任务同行时自动 Y 轴错开（assignLanes）
- 底部图例：完成/进行中/已放弃状态分布

#### 3. 蓝图视图（Root）
- 双栏布局（图左面板右）
- 创建人生主线（目标 + 项目表单）
- 已创建项目列表（颜色圆点 + 状态 + 编辑按钮）
- 本周概览（完成/进行中 + 时长分布 + 报告）

#### 4. 星系视图（Galaxy）
- **Three.js 3D 星系**：恒星=目标，行星=项目，卫星=任务
- 黄金角螺旋分布恒星，任意数量均匀散开
- 卫星状态颜色（金色阶梯）：
  - todo → 淡灰 + 淡金虚线环
  - doing → 亮金实心
  - done/dropped → 暗金 + 金光环
  - overdue（<24h）→ 红色 + 闪烁脉冲
  - breach（≥24h）→ 纯暗灰无环
- 点击恒星 → 操作面板（编辑/摧毁/进入子空间）
- 点击行星 → 进入对应主线的子空间视图
- 视角保持：每次 15s 轮询重建场景后保留用户相机位置

#### 5. 子空间视图（SubSpaceView）
- 点击恒星后进入全屏 overlay
- CSS 太阳系动画：中央大恒星=主线，环绕行星=项目，卫星=任务
- 每个天体可点击打开既有编辑器（GoalEditor/ProjectEditor/TaskEditorDialog）
- 卫星按任务状态上色（金色阶梯配色）
- 反向自转抵消公转，内容保持正向

#### 6. 预警引擎（Alert）
- 24h 到期预警
- 停滞 7 天预警
- 完成/空目标提醒
- 违约物化定时任务（node-cron，每 5 分钟）

#### 7. 隐私星云（Nebula）
- 默认私密
- 逐实体可见度（private/friends/public）
- 好友关系、授权撤回、好友视角预览
- Home 星云视图接入 `<VisibilityManager>` 组件

## 三、关键修复

### 3.1 Bug 修复

#### 快速输入无法解析时间+项目（2026-09-03）
**问题**：输入"今天下午五点跑胶"，无法自动设置截止时间 17:00 和关联项目"凝胶电泳"。

**根因**：
- `OPENAI_API_KEY` 为空 → LLM 解析恒走 fallback（dueAt:null）
- 打字型快速输入直接调用 `createTask`，绕过解析路径

**修复**：
- 新增 `server/parseNatural.ts`：纯规则解析（无需 LLM）
- 支持：今天/明天/后天/下周X/周X/X月X号 + 上午/下午/晚上 X点/X:XX
- 中文数字处理（五点 → 17:00），按用户时区转 UTC
- 按标题部分匹配 projectId
- 集成：`aiTaskService.ts` 在兜底与 LLM 结果后都跑规则解析合并 dueAt/projectId
- `Home.tsx` 打字输入改调 `capture.captureText`（复用文本输入接口）

#### 拖拽到"重要不紧急"（q2）弹回（2026-09-03）
**问题**：任务拖到 q2 后保存，reload 又弹回 q3。

**根因**：`shared/taskRules.ts` 的 `resolveQuadrant` 映射写反：
```typescript
// 错误映射
important + !urgent → q3  // 应为 q2
!important + urgent → q2  // 应为 q3
```

**修复**：
```typescript
// 正确映射（对齐 QUADRANT_FLAGS）
important + urgent → q1
important + !urgent → q2  // 重要不紧急
!important + urgent → q3  // 不重要但紧急
!important + !urgent → q4
```
同时修正 `Home.tsx` 象限标签顺序。

#### 卫星状态颜色不一致（2026-09-03）
**问题**：AnchorGalaxy（3D）和 SubSpaceView（CSS）的卫星颜色逻辑分散，容易漂移。

**修复**：
- 新建 `shared/taskStatusVisual.ts`，提取统一 `taskVisualState()` 函数
- 两个视图共用同一套配色逻辑
- 状态标签拆分：`ENTITY_STATUS_LABEL`（项目状态）和 `TASK_STATUS_LABEL`（任务状态）

#### 甘特图拖拽改截止时间（2026-09-03）
**问题**：甘特图任务条右侧拖拽手柄无功能。

**修复**：
- 添加 `onUpdateDue` prop 到 `WeekGanttChart`
- 拖拽时记录鼠标位移（`lastMouseX`）
- `mouseup` 时计算天数偏移，调用 `onUpdateDue(taskId, newDueAt)`
- `Home.tsx` 透传 `handleSaveTask` 完成跨视图同步

#### 宇宙视图项目状态不显示（2026-09-03）
**问题**：AnchorGalaxy 行星颜色固定，无法反映项目状态；点击行星无反应。

**修复**：
- `Project` 类型扩展：新增 `color?: string` 和 `entityStatus?: string`
- 行星颜色从 `project.color` 读取（fallback 交替色）
- 添加 `onSelectProject` 回调，点击行星进入对应主线的子空间
- `Home.tsx` 透传 `project.color` 和 `project.entityStatus`

### 3.2 踩坑记录

#### Railway CDN 缓存
- **现象**：推送新 commit 后，线上 bundle hash 不变
- **根因**：Railway CDN 缓存旧 bundle（如 `index-D_a5igJI.js` 缓存了多轮）
- **解决**：空提交触发重建（`git commit --allow-empty -m "chore: trigger rebuild"`）

#### 本地 build 第二次失败
- **现象**：`vite build` 第二次报 `[safe-delete] 操作失败`
- **根因**：环境 safe-delete/trash shim 无法清空 `dist/public/assets`
- **解决**：先 `rm -rf dist` 再 build（非代码问题）

#### Three.js canvas 裁切
- **现象**：星系视图从右下角开始，右侧恒星被切掉
- **根因**：`renderer.setSize(w, h, false)` 第三参 `updateStyle=false`，canvas CSS 尺寸未被更新
- **解决**：去掉第三参（默认 true）+ 显式 `style.width/height = 100%`

#### Git 推送失败
- **现象**：`git push` 报 SSL 错误/连接重置
- **根因**：直连 GitHub 不走代理
- **解决**：保留仓库已配置的代理，直接 `git push` 即可

#### Git `.git/refs/` 损坏
- **现象**：`git` 命令全部失效
- **解决**：`git reinit` 比修复更可靠，或直接使用 GitHub API 推送

## 四、架构决策

### 4.1 AI 时间解析策略

**方案对比**：
| 方案 | 优点 | 缺点 |
|------|------|------|
| LLM（gpt-5-mini） | 自然语言理解强 | 需要 API key、网络依赖 |
| 规则解析（纯函数） | 零依赖、即时响应 | 不支持复杂语义 |
| 混合（规则兜底） | 最佳平衡 | 需维护两套逻辑 |

**最终方案**：规则解析作为 LLM 的 fallback，当 `OPENAI_API_KEY` 为空时直接走规则解析。

**关键教训**：
- prompt 必须显式给出**用户本地时间**+星期几+明天/后天的具体日期
- 只给 UTC `toISOString()` 会导致 mini 模型把「明天」误判成「今天」

### 4.2 卫星状态可视化

**金色阶梯配色**（2026-09-01）：
| 状态 | 颜色 | 视觉特征 |
|------|------|----------|
| todo | `#cbd5e1`（淡灰） | + `#fbbf24` 淡金虚线环 |
| doing | `#fbbf24`（亮金） | 实心 + 高 emissive |
| done/dropped | `#b45309`（暗金） | + `#fbbf24` 金光环 |
| overdue（<24h） | `#ef4444`（红色） | 闪烁动画 |
| breach（≥24h） | `#4b5563`（纯暗灰） | 无环 |

**24h 阈值**：`firstBreachedAt` 用于标记首次违约，超过 24h 视为 breach。

### 4.3 隐私分层

**三层可见度**：
- `private`：仅自己可见
- `friends`：好友可见
- `public`：所有人可见

**实现**：`VisibilityManager` 组件 + `trpc.social.setVisibility` mutation，支持逐实体设置。
