# 小程序同步接入说明

## 统一领域契约

小程序端不得自行重算违约状态或改写截止时间。它应将 Goal、Project、Task、关系边、TimeEntry 与周复盘视为云端实体，并通过服务端接口完成所有写入。任务 `importance`、`urgencyMode`、`manualUrgent`、`dueAt`、`doneAt`、`droppedAt` 与 `firstBreachedAt` 的含义与 Web 完全一致。

## 安全配对与首次同步

1. 在已登录的 Web 端进入“迁移与部署”，通过“配对原始小程序”生成**仅显示一次、有效期 30 天**的 Bearer 会话令牌。
2. 在 Taro 开发者工具或受保护设备中调用 `saveAnchorSyncConfig({ baseUrl, sessionToken })`。`baseUrl` 必须是已发布站点地址；令牌不得写入源码、截图或版本库。
3. 第一次迁移调用 `importLegacySnapshot(useTaskStore.getState())`，成功后以 `hydrateCloudSnapshot(snapshot)` 写回服务端权威快照。后续启动时，`app.tsx` 会在已配对的情况下调用 `pullCloudSnapshot()`。
4. 注销或更换设备时调用 `clearAnchorSyncConfig()` 清除本地令牌，再从 Web 端重新生成配对令牌。

> Bearer 会话只能由已登录账户主动签发，小程序不能匿名获取。由于 `automation.configure` 需要浏览器会话向 Heartbeat 转发身份，小程序不得配置服务端定时作业。

| 场景 | 小程序调用 | 服务端保证 |
| --- | --- | --- |
| 首次登录或恢复网络 | `sync.pull` | 返回用户的全量或增量快照，以及服务端 `pulledAt` 时间点。 |
| 新建任务 | `task.create` | 默认重要；当天内到期自动紧急；无截止时间进入 Q3。 |
| 拖动象限 | `task.move` | 持久化人工重要性与紧急性，优先于自动默认规则。 |
| 完成或放弃 | `task.finish` | 追加准时完成、迟到完成或违约后放弃的不可篡改时间事实。 |
| 计时 | `time.start`、`time.stop`、`time.addManual` | 生成真实 TimeEntry，不以任务数量推算工时。 |
| 目标、项目维护 | `planning.*` | 以 Goal—Project—Task 关系驱动周报与动态宇宙。 |

## 本地缓存与冲突处理

小程序可保留最后一次 `sync.pull` 的结果用于离线浏览，但任何编辑应保存在待同步操作队列中。恢复联网后，先提交写操作，再以 `sync.pull` 的云端快照为准刷新本地缓存。对于同一字段的并发修改，首版采用服务端最后一次成功写入为准；任务状态和执行事实不可由客户端覆盖。

> 任务的 `firstBreachedAt` 与 `executionEvents` 是服务端时间事实。客户端只能展示，不得按本地时钟伪造、删除或修改。

## 构建、预览与同步验证

小程序工程继续使用现有的 Taro 应用目录。安装与构建命令如下；若原项目仍固定在 Taro 3.6，应保留与之兼容的 webpack 依赖锁定，避免升级时重新解析到不兼容的插件版本。

```bash
cd taro-app
npm ci --legacy-peer-deps
npm run build:weapp
```

构建产物位于 `taro-app/dist`，在微信开发者工具中导入该目录。小程序配置中应保存已发布 Web 服务的 HTTPS 基地址，并通过 OAuth 或等价的受保护会话换取身份；不得在小程序包内写入数据库、LLM、对象存储或 Heartbeat 凭证。

验收时使用同一账户在 Web 与小程序分别完成以下步骤：创建无截止任务、创建当天到期任务、拖动任务到其他象限、完成一条已逾期任务、启动并停止计时器，再分别调用 `sync.pull`。两端应一致呈现任务象限、人工拖动优先级、完成时间、违约时间事实和 TimeEntry；好友星云仅展示服务端允许返回的摘要。

## 中英文资源

Web 中 `shared/i18nContract.ts` 是当前词典基线，`client/src/lib/i18n.ts` 仅作为兼容转出层。原始小程序已在 `src/i18n.ts` 中实现概览、四象限、周复盘、人生主线和动态 TabBar 的可持久化双语资源；后续新增页面应继续从词典读取，而不能直接写死界面文本。
