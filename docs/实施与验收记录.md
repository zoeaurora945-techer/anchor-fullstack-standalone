# 锚点实施与验收记录

**范围。** 本次实施将原有本地四象限与人生主线原型扩展为以云端账户为中心的全栈系统，并保留原始 Taro 小程序的离线数据路径。Web 使用受保护的云端接口处理 Goal、Project、Task、TimeEntry、周度报告、关系边、好友与可见度；小程序继续使用本地状态和时间事实逻辑，现已补充完整的页面级中英文切换资源。

| 能力 | 当前实现 | 验证状态 |
|---|---|---|
| 云端领域模型 | Goal、Project、Task、TimeEntry、时间事实、周报、好友、授权与活动计时表已迁移并应用 | 已应用数据库迁移 |
| 任务契约 | 默认重要、当天紧急、无截止时间进入 Q3、拖动优先、服务端违约事实不可由 UI 改写 | 单元与路由测试覆盖 |
| 周度复盘 | 完成成果按 Project 聚合；支持计时、手工录入、预览与最终报告快照 | 单元测试覆盖 |
| 动态宇宙 | Three.js 将 Goal、Project、Task 映射为恒星、行星、卫星；档案与人生模式可切换 | 预览已检查 |
| 跨设备刷新 | 工作台核心 Goal、Project、Task 查询每 15 秒刷新，并支持手动刷新 | 已接入前端查询 |
| 隐私星云 | 默认私密；支持好友关系、实体级 private/friends/public 选择、授权撤回、好友视角预览及脱敏 Project 摘要 | 路由测试与预览检查 |
| 小程序语言 | 概览、四象限、周复盘、人生主线、底部 TabBar 均接入持久化中英文资源 | Taro 微信小程序构建通过 |

## 本轮验证结果

全栈项目已执行 TypeScript 检查、Vitest 与生产构建。当前 Vitest 共通过 **7 个测试文件、16 个测试**，覆盖任务规则、时间事实、周度聚合、社交、同步拉取、任务拖动、计时启动、文本 AI 捕获与禁用状态下的定时作业配置。Web 生产构建成功；构建器提示客户端主包约 1.31 MB（gzip 约 353 KB），主要来自 Three.js，建议下一轮将宇宙组件改为按路由延迟加载。

原始 Taro 小程序已执行 `npm run build:weapp` 并编译成功。语言选择写入本地 `meta.lang`，重新启动后继续生效；切换时会同步更新四个 TabBar 标签。由于微信小程序的静态配置机制，首屏的默认导航标题仍以编译时配置为准，而页面内容与 TabBar 会按当前语言更新。

## 仍需在真实账户或发布后执行的事项

> 下列事项依赖真实登录态、用户设备权限或正式发布环境，不能在未认证开发预览中伪造完成。

| 待办 | 原因与执行方式 |
|---|---|
| 原始 Taro 云同步 | 小程序需要先取得与 Web 相同账户身份，再以受认证请求调用 `sync.pull`、`task.*`、`time.*` 与 `planning.*`。当前保留的说明已描述调用契约，但没有绕过 OAuth 或伪造会话。 |
| 登录态端到端验收 | 需在真实账户下测试云端写入、AI 模型调用、麦克风授权与跨设备 15 秒刷新。 |
| Web 剩余文案收口 | 已有共享词典与小程序页面词典；Web 工作台仍有零散的双语条件文本，建议后续统一迁入 `shared/i18nContract.ts`。 |
| Heartbeat 定时作业 | 请先发布站点，再在“迁移与部署”页启用 time_facts、weekly_preview、weekly_final。未发布前不得创建实际定时任务。 |

## 发布顺序

首先在项目管理界面查看最新检查点并确认预览，再点击 **Publish**。发布完成后，使用“迁移与部署”页面配置 Heartbeat 作业。若需让原始小程序接入云端，请以同一账户完成登录，并按 `docs/小程序同步接入说明.md` 中的接口矩阵接线；初次同步建议先从本地 JSON 导入，确认云端快照正确后再开启增量拉取。
